# StemKit MP3 and stems drop box

A small native Windows window containing a drop target and one status line. It stays above your browser so you can drag YouTube video or SoundCloud track titles, linked artwork, or addresses onto it. Dropped links are saved, checked for repeats, downloaded as tagged MP3s, and automatically separated into drums, bass, other, and vocals using Ultimate Vocal Remover's engine. There is no browser interface and no download button.

## Start

Double-click **Start-StemKit.vbs** for a hidden launcher, or **Start-StemKit.cmd**. You can also run `npm start`.

The app needs Node.js 22 or newer, FFmpeg, and ffprobe on PATH. Stem separation also needs Python 3.10–3.12 and Git for initial setup. These have already been configured on this computer. The first launch downloads the official yt-dlp Windows executable to **tools/**, verifies its release SHA-256 checksum, and builds the desktop executable using Windows' built-in .NET Framework compiler. It also creates an isolated Python environment, downloads UVR and the two requested models, and checks the separation runtime. This setup uses several GB and needs Internet access; subsequent launches reuse the installed files. No npm packages or extra desktop framework are needed. **tools/StemKit.exe** can also launch the app.

Keep the drop box open while downloading and separating. Closing it stops processing; accepted links and interrupted jobs resume next time. Only one desktop drop box is allowed at a time.

## Downloaded files

```text
X:\Music\StemKit/
  mp3/
    Artist/
      Song name.mp3
  stems/
    Artist/
      Song name/
        drums.wav
        bass.wav
        other.wav
        vocals.wav
        cover.jpg
        metadata.json
        separation.json
```

The library location is configured in **settings.json** as `X:\Music\StemKit`. The **mp3/** tree contains only artist folders and MP3 song files; there are no song subfolders or separate artwork/JSON files in it. The **stems/** tree contains artist folders, then song folders containing the four WAV files, cover, metadata, and separation record. The drive must be available while processing; StemKit does not silently switch to another location if it is unavailable.

Only the audio stream is downloaded and converted to MP3 using the highest-quality VBR setting. Artist and song tags and the JPEG cover remain embedded in the MP3. The saved MP3 is then automatically analyzed for BPM, key, beat phase, and confidence before stem separation. The separate cover comes from YouTube's thumbnail or SoundCloud's track artwork (with the uploader avatar as SoundCloud's fallback).

Every new download also estimates the song's musical tuning reference from harmonic spectral peaks in several excerpts. `metadata.json` stores the estimated A4 reference as `tuningHz` (for example, `432.015` or `440.002`), plus `analysis.tuningVersion`, `analysis.tuningCents` relative to A4 = 440 Hz, and `analysis.tuningConfidence`. Silence, unpitched audio, or recordings without a consistent reference receive `tuningHz: null`. This is an estimate of an equal-tempered reference, not a song's single fundamental frequency. Note names make references a semitone apart ambiguous, so estimates use the nearest reference to 440 Hz (about 427.47–452.89 Hz).

To analyze already downloaded songs once, run `npm run analyze:tuning`. Preview with `node scripts/analyze-library-tuning.mjs`; add `--apply` to save or `--apply --force` to repeat existing estimates. The script updates only tuning fields, preserves BPM/key and other metadata, keeps previous JSON in **data/metadata-backups/**, and leaves MP3s, covers, and stems untouched. It skips completed estimates on reruns and reports individual failures so interrupted runs can resume. The normal `update:metadata` command also includes tuning analysis.

`metadata.json` in the stems song folder contains only useful song data: source ID (YouTube's video ID or `soundcloud-` followed by the numeric track ID), artist, song title, album/release date when available, audio duration, canonical source URL, download date, BPM, key, and a small `analysis` object holding the algorithm version, source, beat timing, and confidence. The large format/thumbnail lists, description, uploader statistics, stream URLs, and duplicate technical separation details are removed. Key names are readable, for example `Eb minor`; unknown BPM/key values are `null` rather than invented. These are musical estimates. A known BPM is required for automatic stem replacement. Playback tempo and key edits leave these saved original estimates unchanged.

Artist and song fields provided by the source take precedence. If those are absent, a title such as “Artist - Song” is split, otherwise the channel/uploader and title are used. The “- Topic” channel suffix and common official-video suffixes are removed in fallback names. Windows-invalid filename characters are replaced and long names are shortened. If two different tracks share an artist and song name, the second MP3 filename and stems song folder get the source ID as a suffix so neither can overwrite the first.

A download is considered successful only after all three files exist. Failed downloads remain retryable and are never committed to the MP3 archive. Temporary audio and conversion files live in **data/work/** and are removed after completion.

## Automatic stem separation

StemKit runs the separation classes from [Anjok07/ultimatevocalremovergui](https://github.com/Anjok07/ultimatevocalremovergui), pinned to commit `5517e0cf0d1acd16a1618eeedec596957523f9e1`. The full UVR GUI does not need to be open.

| Output | UVR model |
| --- | --- |
| drums.wav | Demucs: v4 \| htdemucs |
| bass.wav | Demucs: v4 \| htdemucs |
| other.wav | Demucs: v4 \| htdemucs |
| vocals.wav | MDX-Net: UVR-MDX-NET Inst HQ 5 |

Inst HQ 5 predicts the instrumental; UVR's native secondary-stem calculation extracts its vocals. Demucs' vocal output is discarded. The four exported stems are stereo, 44.1 kHz, 24-bit PCM WAV files, preserving their alignment without another lossy encoding. Because the vocals use a different model, these four stems are not guaranteed to sum exactly to the original mix.

`separation.json` in each stems song folder records the source MP3's SHA-256, exact model choices, UVR version, audio format, length, and devices used. These technical details stay in that file rather than being duplicated in song metadata. The NVIDIA GPU is used when available; otherwise processing uses the CPU. A CUDA memory error retries the same model on the CPU. Songs are processed one at a time.

Analysis or separation failures preserve the MP3, metadata, cover, and duplicate protection. **Retry failed processing** reuses the saved MP3 in the MP3 artist folder and retries the failed step without downloading again. Saved valid analysis and stems for the same MP3 and models are reused. Interrupted analysis resumes on restart. Temporary stem work is kept in `.work/` inside the stems song folder and removed after successful processing.

Older completed songs without saved analysis are queued for analysis on the next downloader start. To update all existing library metadata immediately, run `npm run update:metadata`; `node scripts/update-song-metadata.mjs` previews the affected songs. The update analyzes MP3s and simplifies their JSON, preserves audio/stems/covers, and keeps the previous JSON in **data/metadata-backups/** outside the song folders.

## Drop box controls

- Drop one link or several links to process them immediately.
- **Ctrl+V**, or right-click → **Paste links**, accepts copied links.
- Double-click the box, or right-click → **Open downloads**, opens your library.
- Right-click → **Open music player** opens the separate desktop player.
- Right-click → **Retry failed processing** retries download or separation errors. Hover over the status line to read the error.
- Right-click → **Pause queue / Resume queue** controls future songs; a current song finishes before pausing.

YouTube watch, `youtu.be`, Shorts, live, and embed links for the same video share a single ID. Tracking, playlist parameters, and timestamps are stripped. Repeats are skipped within a drop, against saved jobs, and against completed MP3 downloads, including after restarting. A repeat of a failed link is skipped; use **Retry failed processing** instead. Playlist-only and channel links are rejected.

SoundCloud track links (`soundcloud.com/artist/track`), private track links, numeric API track links, and `on.soundcloud.com` share links also work through drag-and-drop or paste. Tracking parameters are stripped, while private access tokens are kept in the queue for retries. Share links resolve to a single track before downloading; profile, playlist/set, likes, and other collection links are rejected. The numeric SoundCloud track ID prevents downloading the same track again through a different link, and SoundCloud and YouTube IDs are kept separate. You can mix both sources in one drop. SoundCloud downloads use the same MP3 tags, artwork, BPM/key analysis, and four-stem pipeline.

## Music player

Double-click **Start-Player.vbs** or **Start-Player.cmd**, run `npm run start:player`, or choose **Open music player** from the drop box's right-click menu. **tools/StemKitPlayer.exe** also runs directly. The player is a native Windows app and can run independently of the downloader, using the same library location from **settings.json**.

- Search by artist or song. Select a song and press **Play**, or double-click it.
- Right-click a song in the sidebar, library grid/list, artist folder, or playlist and choose **Add to queue**. This option appears directly above **Delete song…**. Manual choices play before automatic additions, in the order you add them, with Auto play on or off. Choosing an automatically queued song moves its existing entry into the manual group. A transition already playing finishes first; new automatic suggestions and completed downloads stay below manual choices. Queued songs are kept unique, and played songs cannot be added again during that session.
- Hover info boxes are off by default. Enable **Settings → Interface → Show hover info** to see tooltips over controls, song information, and the Camelot key wheel. The choice is saved between sessions.
- Mouse-wheel scrolling in the sidebar, queue, library grid/list, artist folders, playlists, and saved mixes moves smoothly in pixels. Small wheel movements work immediately, and reversing direction changes the motion promptly. Library cards and queue rows reuse bounded rendering caches to keep scrolling responsive. Queue status and metadata updates repaint only changed rows, preserving selection, the visible row, and unfinished scroll motion.
- Each colored stem lane has a real waveform, a source-switch button labeled **VOCALS**, **DRUMS**, **BASS**, or **OTHER**, **M** (mute), **S** (solo), and a volume fader. Stem names appear in bold capitals inside the source buttons; white or black text is selected for contrast against each button's current album color, including disabled buttons. Multiple solos can play together. Muting a soloed part clears its solo; soloing a muted part clears its mute. Muted stems keep advancing and rejoin at the current position. Short gain ramps avoid clicks.
- Drag a song from the sidebar library onto any stem lane. The current song stays loaded and playing; no picker or confirmation screen appears. All four matching stems and waveforms are prepared automatically, and only the dropped lane switches to its replacement. The donor and current song both need completed stems. Dragging a song card from the full library reveals Now playing for the drop; canceling that drag returns to the library.
- Each lane's colored switch button changes instantly between the current song's stem and the prepared donor stem. In the standard view, its stem label, color and waveform match the active song's cover, and the tooltip identifies the source and next choice. Song titles in Now playing use the same chosen cover colors. The most common visibly colorful shade is preferred over white, gray, and pale tints, even when the colorful area is smaller. Covers without a colorful shade keep their neutral selection. Dark colors are brightened for readability. All four replacements become available together, so switching another lane does not analyze or render again. A later drop stages the new song for all lanes but leaves other currently audible lanes untouched. Their next return to Replacement uses the latest staged song.
- Automatic tempo matching reads the BPM and beat phase saved in metadata, with stem analysis as a fallback for older songs. It chooses the closest tempo among the original BPM, half, double, quarter, quadruple, and other powers of two, minimizing the proportional speed change. For example, an 80 BPM donor over a 120 BPM song plays at 60 BPM rather than stretching to 120. Beat phase is aligned automatically. Tempo changes preserve each song's selected key through the native [Rubber Band library](https://breakfastquay.com/rubberband/), processing small buffers during playback.
- Click either song's **BPM** in Now playing to open one shared slider (30–300 BPM). With two songs loaded, both use exactly the selected BPM; with one song, it changes that song's tempo. **Original tempo** restores the original song's BPM and automatic donor matching while retaining selected keys. A known original BPM is required.
- **Settings → Song tuning (A4 reference)** chooses **Original** (the default) or a **Specific frequency** from 300 to 600 Hz, including 432 and 440 Hz. The choice is remembered and applies when songs next load, including replacement stems, saved mixes, and auto-play. Each song uses its own detected reference: playback pitch = target Hz / detected Hz × the selected key-transposition ratio. Tempo processing remains independent, so a BPM change does not add another pitch correction or change the target reference. Resetting tempo or key retains the chosen reference. Unknown tuning skips reference correction; hover over the song's key to see its original and playback reference. Playback and exports use the correction; library audio and original metadata retain their recorded values.
- Click a song's **key** to open the [Camelot wheel](https://mixedinkey.com/camelot-wheel/), with all 24 labeled key sectors. Purple marks the clicked song's current key, yellow its original key when changed, and green the other song's current key. Overlapping keys show multiple fill bands. Click a sector to transpose the selected song independently, or use **Original key** to reset it. Pitch transposition preserves major/minor mode: minor songs select the inner A ring, major songs the outer B ring. A known original key is required; a known BPM is unnecessary for key-only edits.
- Tempo/key changes open and warm small streaming buffers while existing playback continues, then apply through a 20 ms crossfade on the same audio device. They do not render the whole song or its stems first. Existing waveform envelopes are reused and remapped in time; transposition does not trigger a full waveform scan. **Cancel changes** on the original song's key control cancels preparation. Changes retain the musical position, stem selections, faders, mute/solo, and playback mode, and also work with original audio before stems finish. Edits last until another original song is loaded; the library audio and metadata retain their original values.
- A 20 ms crossfade changes sources at the shared current position. Mute, solo, faders, and seeking continue to work. BPM/beat estimates do not guarantee downbeat, song-section, or variable-tempo alignment. A shorter donor ends in silence. Longer donors retain their full matched audio and waveform, so advancing a stem can bring its later sections onto the original timeline, including after tempo/key changes. The shared transport still ends with the original song. **Reset stems** restores every original, clears all stem offsets and loops, clears the prepared song, and cancels preparation without moving playback. It is also available when only offsets or loops have changed. Changing the current song also clears its replacements.
- Choose **Original MP3** to hear the original recording, or **Stem mix** to hear your selected parts. These are alternate playback modes; the original MP3 is not added over the stems.
- **Stem mix**, **Original MP3**, and **Reset stems** sit beside the playback controls. Dropping a replacement shows its square cover on the right, with equal original/added information cards stacked between the two covers. The header keeps the same size; song information shows artist, BPM, and key without duration. Reset clears the added song and restores the single-song layout.

It remembers the original and added songs, each stem's source (including earlier donors still playing), mute/solo, stem and master volumes, offsets, loops, shared tempo, independent keys, and playback mode. When a saved mix is open, the action window offers **Save changes** and **New mix** instead of Save mix. Opening a mix for manual editing turns Auto play off, restores the controls, and waits for Play. Right-click a saved mix to rename or delete it; F2 renames. Deleting it removes its playlist references. This does not export a recording. Saved mixes require their source songs and completed stems. Opening restores their live tempo/key processors directly from those sources, without rebuilding full-song audio caches.
- **Export MP3** in the same **+** window saves the full current song as a stereo 320 kbps MP3. Choose a filename and folder in the save dialog. The export captures the settings when clicked: active stem sources (including earlier donors), mute/solo, stem and master volumes, offsets, loops, tempo/key edits, and playback mode. In **Original MP3** mode it exports the current original audio. Songs without completed stems can export that audio too. It renders from the beginning through the original song's current duration while playback and editing continue independently. Open **+** again for progress and **Cancel export**. Cancellation or encoder failure removes partial output and preserves an existing destination; successful replacement uses the save dialog's overwrite confirmation. Source recordings cannot be overwritten. Export waits for source/tempo/key preparation, stem gestures, and active Auto play transitions to finish.
- Exported MP3s embed a square front cover with a vertical split: the original song cover's left half on the left and the displayed added song cover's right half on the right. The covers are captured together with the mix settings. Single-song exports use the complete original cover; if only one cover is available, that complete cover is used. The 512 × 512 JPEG is stored inside the MP3, and temporary artwork is removed after success, cancellation, or failure.
- Right-click a song in the sidebar, library grid/list, or a custom playlist and choose **Delete song…**, or use **+ → Delete song…** for the current song. Confirm to permanently remove its MP3, complete stems folder (including artwork and metadata), saved YouTube/SoundCloud link, download job and duplicate archive entry. Playlist and queue references are removed too; saved mixes using the song are deleted, with the count shown before confirmation. You can add the same source link again afterward. Removing a replacement restores its affected lanes to the original stems while retaining other timing edits. Playback briefly pauses to release files, then resumes if the current song remains. Deletion waits if that song is still being downloaded/analyzed/separated, if player edits or a transition are active, or during MP3 export. The action works with the drop box closed; when upgrading a running drop box, restart it to enable the new deletion API.
- Open **Library → Playlists → New playlist** to create a named playlist containing songs and saved mixes. Open its card to browse or search its contents, and right-click an item to remove it. Right-click a playlist to rename or delete it; deleting the playlist preserves the songs and saved mixes. **Auto play** inside a playlist shuffles all its available entries once and uses the configured tempo ramp and stem transitions. It stays within that playlist, including when new downloads finish, and stops after the shuffled queue is exhausted. My mixes also has Auto play. Different saved mixes of the same original song remain separate queue entries. Incoming mixes use their saved stem sources, volumes, mute/solo, tempo, and keys. Auto play resets live offsets and loops while leaving the saved record intact; reopening that mix for manual editing restores its saved timing. Turning Auto play off ends the playlist session. Songs without completed stems or a known BPM, and tracks too short for the configured transition, advance through normal playback.
- If the added song's preferred colorful shade is too similar to the original song's color, its next most common visibly different colorful shade is used for its title, source switches, and waveforms. If every colorful option is too similar, white is used, including when the cover has no white pixels. Colors are compared after brightening for readability, which also determines whether a shade is colorful enough. White, gray, and other neutral shades count as similar even when their brightness differs. For monochrome added artwork and a neutral original, a white/light original uses a black/dark added accent, and a black/dark original uses a white/light added accent. The most common opposite shade from the added cover is preferred; if none exists, black or white supplies the opposite fallback. Black is brightened to a readable dark gray. All four stem volume bars use the same color as the master volume bar.
- The filled timeline and played waveform portions use the current album's chosen color. When an added song is shown, including during an autoplay transition, the filled progress blends from the main song's color on the left to the second song's color on the right. Removing the added song restores a single color. Click any waveform or drag the timeline to seek every part together. **Space** toggles play/pause, except while typing in search. **Ctrl+F** focuses search. Sliders accept arrow keys and Home/End; waveform arrow keys seek five seconds.
- Stem keyboard shortcuts follow two rows: **Q / A** switch / mute vocals, **W / S** drums, **E / D** bass, and **R / F** other. Switching toggles the original and added source; muting toggles mute/unmute with the same behavior as the on-screen buttons. They work while browsing or viewing the queue too, respect unavailable controls, and leave search, text fields, numeric editors, and dropdowns available for normal typing. Ctrl/Alt/Shift combinations retain their existing behavior. Holding a key acts once until release.
- With **Auto play off**, **right-drag a stem waveform** in Now playing to offset only that stem relative to the others: dragging right delays it, and dragging left advances it. Release retains that lead/delay rounded to the nearest whole beat at the shared playback BPM. Active loop length appears **above the stem's volume slider**, with the signed beat offset **below it**. The status also says how many beats earlier or later the stem plays. **Hold right click for 1.5 seconds** without moving to loop the nearest complete bar at the pressed position. The loop enters on the next downbeat; drag its highlighted end with either mouse button to resize it in whole bars. You can also keep dragging after the hold to extend it. One bar means four beats. Loops never extend the song's transport. Longer added stems can be advanced by more than the original song's length and loop bars from their retained tails. Timing edits survive pause, seeking, source toggles, and tempo/key changes, and reset when another original song loads or the finished song restarts. Enabling **Auto play** resets all offsets and loops, cancels an active drag or hold, and disables manual timing gestures for as long as Auto play remains on. Turning it off restores the gestures. Beat analysis must finish before timing edits are available.
- Songs automatically match a common playback loudness. The player measures the full original recording using [FFmpeg's EBU R128 loudness filter](https://ffmpeg.org/ffmpeg-filters.html#loudnorm) and aims for −16 LUFS, with at most +12 dB boost to avoid excessive noise amplification. One fixed correction applies to the original and all four stems, including manual replacements, tempo/key edits, preloaded songs, and Auto play handoffs. Muting, solo, faders, and the master volume keep their chosen levels; quiet passages keep their dynamics. Stereo-linked peak protection holds the combined output below −1.5 dB, including when a quiet recording has isolated loud peaks. Measurements are cached in **data/loudness/** and refresh when the original recording changes. Source audio files remain unchanged. A first play may take a little longer to measure; if measurement fails, ordinary playback remains available.
- Adjust master volume; use **Previous** / **Next** to navigate the session queue. Previous loads the previous song from its beginning, including after more than three seconds of playback and with Auto play on or off. With Auto play on, Next prepares a beat-matched transition from the current song's ongoing position, preferring a nearby bar or beat within five seconds once ready. The current song keeps playing while its new outgoing excerpt is prepared. If playback passes that excerpt before it is ready, a later excerpt is rendered; an old section is never moved to a different playback position. Manual Next can continue past the configured end cut to preserve the current passage. Beat matching takes priority over quiet vocal phrases: tempo matching finishes, then the stems switch on their configured musical intervals. Preparation already in progress continues, and the loaded incoming song, its waveforms, and the following song's preload are reused. Normal Auto play retains its configured transition planning. Pressing Next during a transition skips the remaining transition and immediately continues the incoming song with all its stems, at its current position, using the same audio output and prepared audio. With Auto play off, Next loads the next queued song immediately.
- With **Auto play off**, a natural song ending plays the next unplayed queued song, or a random unplayed library song when the queue has no unplayed next entry. Played songs are excluded throughout the session, including in a one-song library. Playback stops when no unplayed song remains. The successor starts normally and gets its own session-queue entry, so Previous and Next retain the played history. Pause holds advancement.
- **Auto play**, beside Library and also at the top of the library view, starts shuffle with transitions. Near the end of the current track, its tempo gradually changes to a matching BPM for the next track while preserving pitch, including half/double time and further powers of two. For example, 156 BPM ramps to 160 BPM for an 80 BPM incoming song. The incoming audio plays at its original tempo, and stem-change bars use that song's original BPM. Only after the tempo ramp finishes do the incoming stems replace the outgoing stems, one at a time. The incoming song keeps advancing during each stem change; after the last change it becomes the current song and continues from that position. The same audio output handles the whole sequence.
- Open **Settings** with the gear beside the **+** add songs button in the Now playing sidebar. Under **Auto play**, set how many BPM slower/faster the next song may be, the tempo-change duration in bars, the bars between stem changes, and **Cut off song ending**. The end cut moves the transition earlier by that many bars at the current playback BPM: four bars at 120 BPM starts eight seconds earlier. It supports 0–64 bars in quarter-bar increments, defaults to zero, and keeps the tempo-ramp and stem-change durations. Starts remain aligned to bars; fractional cuts may round the start earlier to the preceding bar. An oversized cut keeps at least one playable bar (or the entire song if it is shorter); both prepared transitions and preparation loops exclude the discarded tail. The preview shows the approximate seconds at the current BPM. Select a stem and use **Move up** / **Move down** to set the order. One bar means four beats. Other defaults are −10/+10 BPM, eight bars for the tempo ramp, four bars between stems, and drums → bass → other → vocals. A zero-bar tempo ramp changes tempo immediately; stem spacing supports quarter bars and longer.
- Auto play starts with the **standard waveform view and source-switch features** in every player session. Points move independently throughout the entire transition range: IN can precede OUT for an overlap, OUT can precede IN for a gap, and different lanes can share a point. Points remain editable after playback passes them; a change immediately adjusts the audible mix. Right-clicks snap to the nearest beat or estimated vocal phrase break; **Shift + right-click** places a point at the exact clicked time. Stem waveforms and source cards have no hover instruction popups in the editor. Outside the editor, seeking, source buttons and their keyboard shortcuts keep their previous behavior. Loading already in progress also continues through seeks. Seeking into the prepared transition positions the existing audio at that song time. Changing the next queued song still prepares a new transition.
- The final transition handoff continues at the exact next incoming audio frame through the same output, preserving live fader ramps and peak protection. Closing the finished song's decoders does not hold up playback.
- Enable **Transition fading or quiet stems early** in Auto play settings to avoid loud peaks in both the outgoing and incoming stems, while still taking advantage of sustained fades and quiet endings. It defaults to off. Vocals get first choice of a quiet phrase boundary; drums and other follow with less strict peak avoidance, then bass. Brief gaps between words are ignored. Outgoing vocals can end before incoming vocals start, leaving a silent gap until the next quiet lead-in or verse onset. Different stems' cutoffs and starts stay separated, and their timing can move around the configured order. Phrase boundaries are estimated from stem volume. The planner can look ahead up to eight bars (at least four seconds), limited by the incoming song's available audio, and extend the handoff when needed. - Shuffle uses songs with known BPM, finished stems, and enough audio for the stem handoff. It includes songs whose BPM, multiplied or divided by powers of two, falls within the inclusive BPM range relative to the current playback BPM. With 156 BPM and −10/+10 limits, 80 BPM qualifies as 160 BPM, and 40 BPM qualifies the same way. If several equivalents fit, the ramp uses the one requiring the smallest proportional tempo change. Shuffle excludes songs already played or queued in this session. Exhausting the eligible pool does not restart it; the current song finishes and playback stops if no unplayed eligible song remains. Transitions use the stem mix and retain faders, mute/solo, and master volume. BPM/key edits and seeking are available outside an active transition; manually selecting another song cancels the pending transition. Settings changes apply to the next prepared transition. Pause freezes the transition on its current audio frame. Turning Auto play off cancels pending preparation; an already-playing transition finishes its current handoff.
- Transitions are prepared in the background. If the next song is still loading or its transition window has passed, Auto play chooses a musical replay: vocals fade out at an estimated phrase ending, drums guide a backward jump to an earlier interior section, and vocals fade back in at a phrase beginning. Departure and return favor quiet drum lead-ins just before a hit, or valleys before a rising drum peak when no silence is available. Fine drum timing and matching drum patterns preserve kick/snare spacing; bass/chord similarity also helps avoid an obvious cut. The opening bar and first beat are excluded, including fallback replays, and the join may happen before the calculated transition. Partial intro/tail bars and the configured end cut are excluded. When no clear vocal break is available, bar/beat boundaries provide a fallback. Auto play uses the stem mix so vocals can be controlled independently. A short outgoing track can repeat its outro to fit the configured transition bar counts. Library audio and metadata are preserved. Auto play preferences are saved, but reopening the player still waits for Play before resuming playback.

Once the immediate next song's transition is fully ready, the second song starts preparing automatically. Its analysis, full audio, four stems, waveforms, tempo ramp, stem-change timing, and playback mixers are all prepared ahead and reused for the following handoff, including work still in progress. As playback advances, the queue refills to ten upcoming songs. Queue rows show **Preparing ahead** while this work runs and **Ready ahead** only after the complete handoff is ready. Reordering/removing the successor replaces or cancels that work; turning Auto play off, selecting another song, or ending the session cancels it. Background failures leave the active handoff and queued song intact, and preloading never marks a song played. Loading is limited to one speculative future song at a time and releases file handles before artist folder renames.
- When the incoming song has too little time for the following transition, Auto play plans a replay using the next queued song's BPM, configured ramp/stem spacing and end cut, bar alignment, and measured preparation time. Once the vocal exit has begun, a newly ready transition waits for that loop to finish, then starts at its calculated position on the replayed pass. The delayed vocal entry survives this handoff. If a very short song places the calculated transition at its beginning, its outgoing excerpt is rebuilt from the interior replay point so entering the bridge cannot jump back to the intro. Replays retain queue position, session history, user mute/solo, faders, and master volume; automatic vocal gating never changes those controls or adds a duplicate song. A short audio crossfade smooths each instrumental splice without shifting the incoming drum hit; joins at the usable audio ending retain a brief sample ramp. Excerpts shorter than one bar use an interior beat or excerpt when available. Pausing holds playback and replay timing, seeking refreshes the waiting loop without canceling Next, and turning Auto play off or ending the session removes the repeat and automatic vocal gate. With no successor available, the last song finishes normally.

The player streams the WAVs from disk through one shared audio output, rather than loading full songs into memory or playing four independent devices. It reads 24-bit stems, mixes floating-point samples, clamps output to prevent digital overflow, and sends stereo PCM to Windows. Original MP3 playback uses Windows Media Foundation and resamples to the stems' sample rate where necessary. Using a different model for vocals means a full stem mix can sound slightly different from the original MP3.

Master volume, individual faders, mute/solo states, playback mode, the last selected song, Auto play settings, saved editable mixes, and custom playlists are remembered in the app's internal **data/player-settings.json**. The playback queue and active playlist Auto play session belong to the current session. Earlier on/off preferences are migrated automatically. Audio files, cover art, and metadata are read without being modified. Waveforms are analyzed in the background and cached in memory; full song samples are not retained. Closing the player releases audio and file handles and leaves the downloader running.

Music analysis is cached in **data/music-analysis/**. Transformed WAVs are cached in **X:\\Music\\StemKit\\matched-stems\\**, configured by **matchedStemsRoot** in **settings.json** (projects without that setting use **data/matched-stems/**). **Settings → Matched-stems storage → Maximum folder size** changes the cache budget in GB, in 0.1 GB steps; the default is **30 GB (30,000,000,000 bytes)**. The choice is saved as **matchedStemsMaxGb** in **settings.json**. Saving a smaller budget immediately deletes the least recently used generated files until the cache fits, stopping as soon as enough space is reclaimed. Playing audio, staged replacements, and prepared Auto play audio are protected; if they exceed the new limit, the player reports that cleanup is pending and retries as files become available. Cleanup also runs at player startup, every ten minutes while the player is open, and before new renders. Space is reserved before rendering, including temporary WAVs; if protected audio fills the budget, new renders stop with a message until space can be reclaimed. Download analysis caches use a hash of the MP3 contents and analysis script; player fallback caches and transformations use source file identity and transformation settings. The player does not rewrite library files. The prepared donor and source selections last for the current player session. ## Live tempo and key runtime

The player follows [Mixxx's streaming Rubber Band scaler](https://github.com/mixxxdj/mixxx/blob/main/src/engine/bufferscalers/enginebufferscalerubberband.cpp): independent tempo/pitch ratios, bounded buffers, stereo processing, and compensation for startup padding and latency. Each original or donor stem has its own virtual timeline, preserving longer tails, beat offsets, loops, and seeking. MP3 exports open independent processors with the frozen playback settings. Manual edits and replacement matching read source audio directly; repeated edits do not stretch earlier renders.

Player setup copies the 64-bit Rubber Band runtime and its dependencies from the installed **C:\Program Files\Mixxx** into **tools/**. For another installation, set **STEMKIT_RUBBERBAND_DIR** to the Mixxx DLL folder. Later launches reuse those local files; Mixxx does not need to be running. Setup records the source paths and SHA-256 hashes in **tools/player-packages/realtime-receipts.json** and retains the supplied license notices. See **THIRD-PARTY-NOTICES.md**.

Run `npm run test:realtime` for audible tempo/pitch independence, coherent stereo, exact virtual lengths, alignment silence and trimming, repeatable seeks, immutable export processors, loops, source toggles, same-device handoff, and long-song startup/throughput. Its Apply fixture deliberately blocks the offline render gate and points FFmpeg at a missing executable, ensuring manual tempo/key changes cannot fall back to full-song rendering. It reports measured startup and Apply timings for a three-minute song.
